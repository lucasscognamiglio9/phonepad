# P02-03: negociación y modo de solo visualización

## Alcance

Este bloque agrega una negociación aditiva para el WebSocket de control. La
ruta antigua `/ws` sigue hablando el saludo `{"t":"ok"}` y acepta los
comandos sin época. Un cliente que abre `/ws?protocol=2` recibe un saludo
`{"t":"ok"}` ampliado y debe enviar `sessionEpoch` en cada comando de
entrada. `ping` no lleva época.

El servidor anuncia `protocolVersion: 2`, `compatibleVersions: [1, 2]`, una
revisión monotónica de capacidades, los roles, los cuatro permisos y las
capacidades de entrada, texto literal y video. `source` y `geometry` se
anuncian como `unavailable`; el servidor todavía no obtiene esos datos de un
proveedor real. `video` queda en `unknown` y ofrece `query_preview_status`
como razón de consulta.

Los permisos sólo usan `granted`, `revoked` y `unavailable`. Las capacidades
usan `available`, `unavailable`, `unsupported` y `unknown`. Si el host no
tiene proveedor de entrada, el permiso y las capacidades de entrada quedan
`unavailable` con `provider_unavailable`; el proceso continúa como servidor
de solo visualización. La opción `--demo` conserva un inyector explícito y
publica `capabilities.input.effective: false`.

Una revocación de entrada incrementa la revisión, retira las operaciones de
texto preparadas, libera el inyector y envía una actualización de capacidades
por la conexión vigente. La conexión y la vista previa permanecen activas.
Un comando de entrada rechazado recibe `t: "rejected"` y no cierra el
WebSocket. Las consultas de estado y las cancelaciones de operaciones de
texto retiradas siguen disponibles y la cancelación es idempotente.

La captura de video no se puede detener desde este servidor. Por eso
`SetPermissions` rechaza cualquier cambio de `view` que no sea `granted` y
conserva el estado anterior. La revocación efectiva de la captura queda para
el proveedor de P07.

## Época y permisos para futuras mutaciones

Cada conexión recibe una época aleatoria independiente de `inputSession`.
Renovar la cuota de texto puede cambiar `inputSession` sin reutilizar la época
del control. Para archivos y portapapeles, el servidor expone dentro del
paquete `server` estas operaciones:

```go
permit, ok := s.captureMutationPermit(mutationScopeFiles)
err := s.runPermittedMutation(permit, func() error {
    return publishOrCopy()
})
```

Los alcances disponibles son `mutationScopeInput`, `mutationScopeFiles` y
`mutationScopeClipboard`. La captura sólo lee el estado bajo `s.mu`. La
revalidación toma `mutationGate` y `s.mu` justo antes del efecto. El código que
lee un upload no debe sostener ese gate. Un cambio de permisos o de conexión
incrementa la revisión y vuelve obsoleto el permiso capturado.

La sustitución o desconexión de una sesión usa el mismo orden
`mutationGate` y luego `s.mu`. El cierre del socket y las notificaciones quedan
fuera de esos locks. Un cambio de sesión espera sólo el efecto acotado que ya
pasó la revalidación y después invalida la época anterior.

El orden de locks para los consumidores que integren almacenamiento es
`store.mu`, `mutationGate`, `server.mu`. `SetPermissions` no toma el lock del
almacenamiento. Así la revocación no espera la lectura de un cliente lento.

## Archivos modificados

- `daemon/main.go`: inicia sin inyector cuando el proveedor físico no está
  disponible y sólo envuelve/cierra un inyector existente.
- `daemon/internal/server/server.go`: negocia la versión, asigna la época,
  valida comandos v2 y mantiene el ruteo de ping y la compatibilidad v1.
- `daemon/internal/server/input_operations.go`: valida la época para HTTP v2,
  conserva estado/cancelación después de revocar y devuelve la época nueva al
  renovar la cuota.
- `daemon/internal/server/protocol.go`: admite `sessionEpoch` en el sobre de
  comandos.
- `daemon/internal/server/capabilities.go`: contrato de capacidades, permisos,
  revisiones, rechazo no fatal y permisos para efectos acotados.
- `daemon/internal/server/capabilities_test.go` y
  `daemon/internal/server/input_operations_test.go`: pruebas de v1/v2,
  épocas, ping, revocación, proveedor nulo y permisos de mutación.

## Límites

Este bloque no implementa proveedores nuevos, geometría, codecs, parada de
captura ni permisos de pairing por dispositivo. Las rutas de archivos y
portapapeles ya integran los permisos; ver `p02-03-files.md`. La evidencia
física y la aceptación de video siguen pendientes.

## Integración y verificación

El cliente móvil usa las capacidades efectivas para separar visualización,
entrada, archivos y portapapeles. Un cambio de permisos conserva borradores,
recibos y selección de fotos. Consultar o cancelar una operación de texto
usa la época actual y conserva la identidad original de su lease. El selector
nativo puede suspender temporalmente la conexión sin descartar fotos.

La revisión cruzada encontró y corrigió tres incompatibilidades antes de
guardar el checkpoint: el tipo del saludo inicial, la ausencia de época en
HTTP de texto y la pérdida del código de cierre 1008 al reemplazar un cliente.
El cierre 1008 ahora ocurre fuera del saludo nuevo, sin que dos clientes
intenten recuperar el control automáticamente. También se eliminó una
inversión de locks entre commit y subida de fragmentos.

Pasaron 169 pruebas móviles, TypeScript, Go completo con `-race`, `go vet` y
compilación del daemon. La suite Go incluyó `TestMobileSessionInterop`, que
ejecuta las clases TypeScript reales frente a HTTPS y WebSocket del servidor
Go con un inyector sintético. Comprueba Unicode fragmentado, revocación,
consulta tras reconectar y ausencia de reenvío. Para repetirla, establecer
`PHONEPAD_MOBILE_INTEROP` a la ruta absoluta de
`tools/refactor/p02_session_interop.cjs` y ejecutar esa prueba desde `daemon`.
Necesita Node y las dependencias instaladas en `mobile`.

Evidencia en `outputs/p02`: `negotiation-go-race.log`,
`mobile-negotiation-tests.log`, `negotiation-typecheck.log` y los exports
Hermes `negotiation-ios-export` y `negotiation-android-export`. Los bundles
terminan en `9a82f3b5e1605f578288eb7e8bed9d4e` y
`60055a5d36cd24e103dd9158fbde7c92`, respectivamente. Son bundles JavaScript,
no IPA/APK ni aceptación física. No hubo despliegue ni OTA.
